Export cookies from Chrome

Take your cookies to curl, wget, a test script or another browser, without them going anywhere else.

Chrome has no export button for cookies. A cookie editor can make one, but an export holds your logins, so pick one you can check. cookieZ makes no network requests and its code is public.

Make the export

  1. Open the site in Chrome and click the cookieZ icon.
  2. Under the delete options, choose which cookies: This page, This domain and its subdomains or All sites. Nothing is deleted: export uses the same choice. To export only some, search or tick them first.
  3. Click Export and choose a format.
  4. Add a password if you like, then click Copy or Download.

Which format?

  • JSON: keeps every detail. Imports back into cookieZ and other cookie editors.
  • cookies.txt: the Netscape format, for curl (curl -b cookies.txt), wget (wget --load-cookies cookies.txt), yt-dlp and similar tools. It can't hold SameSite or partitions. For yt-dlp, see Export cookies.txt for yt-dlp.
  • Playwright: a storageState file, for starting a test already logged in.
  • Selenium: Python add_cookie() calls for a test script.
  • Cookie header: names and values for one site, to paste into a request.
  • curl command: a ready-to-run command that sends these cookies to the page.

Import them again

Click Import and paste, or open cookieZ in a tab to choose a file. It reads its own JSON, other cookie editors' JSON, cookies.txt, Set-Cookie lines, a Cookie header and a curl command from "Copy as cURL" in DevTools. You see what will be added before anything changes. To copy cookies from a staging site to localhost, open cookieZ on localhost and tick Put them on this site instead.

Keep it safe

Anyone with an export can sign in as you until those logins expire. Don't paste one into a website, a chat or a bug report. With a password, the file is locked on your computer using the browser's own encryption, and only cookieZ can open it again. The password isn't saved, so don't lose it.
