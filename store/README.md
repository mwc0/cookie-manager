# Store listing assets

What goes into the Chrome Web Store submission.

| File | What it is |
| --- | --- |
| `LISTING.md` | Every text field in the Developer Dashboard, ready to paste: name, summary, description, single-purpose statement, permission justifications, data disclosures. |
| `PRIVACY.md` | The privacy policy. The store needs a URL for this; `LISTING.md` says which URL to use. |
| `screenshots/` | Five 1280x800 PNGs, generated by `tests/make_store_screenshots.py`. |

The store also asks for a 128x128 icon. That one ships with the extension and
lives at `src/icons/icon-128.png`, generated by `tests/make_icons.py`.

## Decided: the listing does not name EditThisCookie

Settled, so it does not need relitigating. Naming it would likely reach
people searching for the extension they lost, but it is a live extension
under someone else's ownership: that risks a trademark complaint and a
takedown, it edges toward the keyword-manipulation the store's policy
prohibits, and a security-adjacent tool that looks like it is trading on
another product's name works against the trust the whole listing is built
on.

The description says what the extension is without naming anyone. If the
context ever seems worth adding, the defensible form is one sentence of
plain fact, not a keyword in the title or summary:

> Built as a Manifest V3 replacement for the kind of cookie editor that
> stopped working when Chrome retired Manifest V2.

## Screenshots

Five are done, in `screenshots/`. Regenerate them after any UI change with:

```
cd tests && python make_store_screenshots.py
```

They're generated rather than hand-captured so they can't quietly go stale
against the UI. The script seeds cookies on `example.com` (reserved for
documentation, so no real service's branding ends up in the listing) with
obviously fake values, drives the popup into each state, and composes each
capture onto a 1280x800 canvas with a caption.

| File | Shows |
| --- | --- |
| `01-overview.png` | The table: every cookie for the current site. |
| `02-delete-scope.png` | "All sites" selected, with the count and the full list of domains expanded. The headline feature. |
| `03-edit.png` | The editor mid-create, all fields visible. |
| `04-search.png` | A filter active with the "just the cookies shown" scope selected. |
| `05-keep.png` | A kept row, its Delete disabled, and the summary saying what will be left alone. |

Upload them in that order. The store shows the first one largest, and the
second is the answer to the "delete all doesn't actually delete all"
complaint that the whole product is aimed at.

Two notes on how they're made, in case you ever adjust them:

- The popup is captured at 2x and placed at its natural 780px width rather
  than upscaled, so the text stays sharp.
- Where the popup's content genuinely scrolls, the bottom is softly faded.
  That's deliberate: a frame that ends mid-row reads as a broken screenshot,
  whereas a fade reads as a list that continues. It isn't hiding anything the
  user wouldn't see. The popup really does scroll there.

## Before you submit

- [ ] Re-run `tests/make_store_screenshots.py` if the UI changed since the
      screenshots were last generated, and look at all five
- [ ] Re-read `PRIVACY.md` and confirm every claim is still true of the code
      you are shipping. It is written in absolutes, which is only an asset
      while it stays accurate
- [ ] Check the version number in `src/manifest.json` (still `0.1.0`; the
      feature set is the planned v1, so `1.0.0` is the natural release)
- [ ] Add an entry to `CHANGELOG.md` for the version being submitted, moving
      it out of Unreleased
- [ ] Zip **the contents of `src/`**, not the repo root and not the `src`
      folder itself
- [ ] Confirm the zip contains no `tests/`, no `docs/`, no `.git`
